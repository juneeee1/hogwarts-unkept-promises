# 入学之夜：失落的星图（讨论稿）

2026-09-07。本文是下一阶段的玩法建议，尚未加入当前游戏。当前版本只修改魔杖、移动界面与分院帽模型，分院仍没有正式判定或存档。

## 推荐的第一版

做一段约 20–30 分钟、可以完整通关的单人轻解谜冒险。保留自由漫游，另设故事模式。玩家在分院晚宴后收到一封迟到的信：天文塔的一幅星图被魔法拆散，只有在午夜前找齐它的三部分，才能看见学校送给新生的秘密。剧情为同人原创，借用魔法学校的建筑、分院帽、画像与魔咒氛围，不把原创谜题说成原著事件。

核心循环是「观察异常 → 对准物件施法/操作 → 场景发生可见变化 → 得到线索 → 去下一处验证」。每次完成交互都改变环境，而不是只弹一句话或增加数字。失败给出可理解的线索和小插曲，可以立即重试。第一版不用体力、抽卡或付费解锁。

三件关键物品是图书馆的星图残页、魔药教室的显影墨水、画像回廊的观星镜片；庭院负责把三条线索联系起来，天文台负责最终解谜。先把一条主线做完整，四学院通过局部内容产生差异。

## 七个场景各自怎么玩

| 场景 | 玩家实际操作 | 可见反馈与剧情作用 |
| --- | --- | --- |
| 石桥 | 对准熄灭的路灯使用荧光闪烁，找出灯下的信封 | 依次亮起的灯引向城门；漂浮的信落到玩家面前，学会移动、环视、对准互动 |
| 礼堂 | 坐到分院帽前，以三个小情境作答，再表达自己的倾向 | 帽子回应选择，宣布学院；相应旗帜、烛光、随身手记和魔杖饰带发生变化，收到所属学院的第一条线索 |
| 庭院 | 修复破裂的喷泉浮雕，再转动星盘对齐浮雕中的三个符号 | 泉水恢复，水面映出三个场景的线索；可随时返回这里查看下一步提示 |
| 图书馆 | 用荧光闪烁照出书页边注，把三本错位的书放回正确位置 | 书脊连成星座，书架打开暗格，取出星图残页；飞走的书和轻声提醒作为可选彩蛋 |
| 魔药教室 | 读取配方，按顺序放材料，并沿指定方向搅拌 | 液体颜色、泡沫和蒸汽随步骤变化；正确时得到显影墨水，错误时冒出小蘑菇或彩色泡泡，再试即可 |
| 移动楼梯与画像 | 与画像交流线索，点击楼梯机关调整接驳方向，走到目标楼层寻找失落画像的画框 | 楼梯真实转动并承载玩家；帮助画像归位后交出镜片。提示留在肖像/画框中，无需键盘快捷键或严格计时跳跃 |
| 天文台 | 给残页涂上显影墨水、装回镜片、转动望远镜对准三颗目标星 | 星点与纸上的缺口逐一重合，完整星图映到穹顶；触发学院对应的结尾寄语，生成本地纪念页 |

手指操作保持三种：拖动环视/移动、点击施法或互动、少量拖拽物件。靠近可互动对象时出现简短动作提示；必要时进入物件近景，给手机留出足够操作面积。谜题读物可放大，界面退出后恢复原位置与朝向。无精细瞄准、快节奏连按和掉落惩罚。

## 分院怎样影响后续体验

分院应当影响探索途径和角色反馈，而非只有换一个徽章。用三段情境选择推断倾向，分院帽解释原因，玩家可以坚持自己的学院；选择确认后保存，同一局不会因刷新重新分院。

| 学院 | 第一版的具体差异 |
| --- | --- |
| 格兰芬多 | 画像邀请玩家先踏上移动阶梯，完成一次勇气试炼便主动提供镜片线索；偏直接行动的对话与成就 |
| 拉文克劳 | 书页多出可解读的星象边注，通过符号规律可提前推导书架顺序；偏观察、推理的支线 |
| 赫奇帕奇 | 帮忙照料庭院的小植物、找回画像的同伴后，NPC 会提供更直白的提示；偏耐心、互助的支线 |
| 斯莱特林 | 可与守门画像交换线索，利用旧口令打开回廊近路；偏交涉、策略的支线 |

核心场景、基础魔咒和主线结局对所有学院开放。四学院均有积极特质，不用学院决定善恶。第一版共享主线，仅做学院专属线索、一次特色互动和结尾寄语，避免四条大支线拖慢制作。纪念页记录学院、发现的秘密和一句画像赠言，使用本地模板，不调生成接口。

## 单机与 Storvia 的支持边界

主线解谜、分院判断、对话选项、互动动画、环境反馈和纪念页均可通过本地代码与预写内容完成，不需要 AI 生成。资源加载完成后，可独立运行；若要承诺关页后断网重开，则需要额外做离线缓存，当前版本没有此能力。

Storvia 官方 `save.get()/save.set()` 支持任意 JSON 存档，按游戏会话隔离，整个存档上限 256KB，并且不注入 AI。建议保存学院、任务阶段、谜题状态、收集品、已读对白、版本号；位置按检查点保存，避免逐帧写入。普通浏览器版使用本地存档；平台版初始化成功后使用平台存档。同步失败要保留本地待写状态、提示未同步，不能把空存档当成已通关数据覆盖。`save.set()` 是整体覆写，写入需要排队合并。

来源：[Storvia 属性与游戏存档](https://docs.storvia.ai/docs/creation/world-mode/state)。Storvia 预览模式的状态不持久保存，云存档验收需要发布后的实际会话，不能只凭本地预览下结论。来源：[快速开始](https://docs.storvia.ai/docs/creation/world-mode/getting-started)。

## AI 只做玩家主动选择的附加体验

如果希望增加陪伴感，建议第二阶段只开放「与画像自由交谈」或「向分院帽自由提问」。主线答案、道具获取与分院结果仍由明确的游戏规则维护。AI 可以用当前学院和已完成任务组织回应，不能修改付费状态、凭空发道具或改变已确认的学院。

玩家流程：点击指定 NPC → 先显示免费的预写对白及选项 → 玩家另点「自由交谈 · 将消耗花园币」 → 输入并主动发送 → 只发起这一条生成。进入场景、靠近 NPC、分院、施法、读线索、存档、恢复页面都不触发新的付费生成。若平台能提供可靠的本次价格，发送前展示；在未核实计价接口前，不编造具体币数或承诺固定费用。

必须落实的计费行为：

- 发送后立即锁定该请求的入口，跨组件共享在途状态，避免快速连点重复提交；一条指令不扇出给多个 NPC。
- 断线先恢复已有生成或读取已完成消息，不自动再次调用 send/generate/retry。恢复失败保持待核对状态，由玩家主动决定是否重新生成。
- 「重新生成」必须由玩家再点击，清楚说明会再次消耗花园币；返回页面不得自动执行。
- 停止生成不是撤销账单，官方说明已经产生的内容仍计费，界面文案不能说“取消后不扣费”。
- 官方文档未说明通用请求幂等键或固定价格查询 API。客户端锁定只能防误触，不能单独保证支付恰好一次。接入前需对平台实际 SDK/账单核实异常、刷新、多端与重连行为；无法确认时，先不上付费 AI。

这些约束来自平台当前接口：`send/generate/retry` 均扣费；`resume` 不发起 AI、不扣费；同一 topic 的在途生成有并发互斥。互斥不等于跨时间重复请求去重。来源：[Storvia 聊天 API](https://docs.storvia.ai/docs/creation/world-mode/chat)。

## 建议的实现顺序

1. 先完成「礼堂分院 → 图书馆取残页 → 天文台小结局」的可玩样段，验证分院差异、手机交互与存档。此时还不能宣称七场景完整主线完成。
2. 接入庭院、魔药、画像楼梯，串成上面的完整一夜冒险；添加四学院反馈、分层提示和可选秘密。
3. 完成横竖屏、重新载入与断线恢复、低性能设备验证，再考虑 AI 自由交谈。

需要一起决定的是体验重心：优先做轻解谜探险，还是改为校园生活与角色陪伴。推荐第一种：当前城堡空间、魔杖和移动楼梯已经具备基础，能更快形成一段有开始、有变化、有结尾的完整游戏。如果更偏角色陪伴，则需要把后续投入改向人物、对话、关系与日常事件，任务谜题相应减少。
